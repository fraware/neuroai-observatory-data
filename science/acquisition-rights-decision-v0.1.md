# Phase 4 acquisition rights decision v0.1

**Decision date:** 2026-08-25  
**Scope:** `SCIENCE-QUERY-COMPILATION-V0.2` / `SCIENCE-QUERY-PLAN-A9B8B8999861882C4BC7`  
**Providers in executable plan:** Crossref and Europe PMC  
**Decision type:** engineering/data-governance release control; not legal advice

This document records the artifact-level release decision required before any Phase 4 provider-derived material may move beyond internal acquisition custody. It deliberately separates permission to access an API from permission to redistribute the resulting material.

The decision is fail-closed. An artifact class not explicitly listed as `PUBLIC_REDISTRIBUTION_PERMITTED` remains unavailable for public release through the Phase 4 pipeline.

## Decision states

- `PUBLIC_REDISTRIBUTION_PERMITTED`: the cited official source material supports public redistribution of the scoped artifact class, subject to the conditions in this document.
- `INTERNAL_CUSTODY_ONLY`: the artifact may be retained for internal acquisition custody/audit under the supported access route, but this review does not authorize public redistribution.
- `PER_RECORD_OR_CASE_REVIEW`: public release requires additional review of the exact record/content/source or an explicit provider/legal determination covering the retained fields.

## Official sources reviewed

### Crossref

1. Crossref REST API documentation: https://www.crossref.org/documentation/retrieve-metadata/rest-api/
   - states that the public REST API exposes scholarly metadata;
   - states that almost none of the metadata is subject to copyright and may be used for any purpose;
   - specifically warns that some abstracts may remain copyrighted by publishers or authors.
2. Crossref metadata retrieval licensing guidance: https://www.crossref.org/documentation/retrieve-metadata/
   - states that almost all Crossref metadata is reusable without restriction;
   - identifies abstracts as the principal exception;
   - states that Crossref-generated data, including aggregations, is released as public-domain material.
3. Crossref current membership terms: https://www.crossref.org/membership/terms/
   - section 5 states that all Metadata and Identifiers registered with Crossref are made available for reuse without restriction through public APIs and search interfaces.

### Europe PMC

1. Europe PMC Articles RESTful API: https://europepmc.org/RestfulWebService
   - identifies `lite` as the result type returning key metadata;
   - documents REST as a supported programmatic access route.
2. Europe PMC developer resources: https://europepmc.org/developers
   - presents Europe PMC APIs and bulk mechanisms as supported routes for Open Access content and metadata;
   - states that automated bulk retrieval must use the supported API/OAI/bulk mechanisms.
3. Europe PMC copyright notice: https://europepmc.org/Copyright
   - states broadly that material available through Europe PMC may remain protected by publisher/author copyright;
   - places responsibility on users to comply with applicable copyright restrictions;
   - states that even material distributed through REST/SOAP/OAI/bulk services may remain copyright-protected and that license terms are not identical across articles.
4. Europe PMC downloads page: https://europepmc.org/downloads
   - provides supported bulk downloads, including metadata for full-text Europe PMC articles and identifier mappings;
   - does not establish, for this review, a blanket field-level redistribution grant covering every arbitrary `lite` search response returned across all Europe PMC source databases.

## Explicit exclusions

This decision does **not** authorize release or ingestion expansion for:

- Crossref abstracts;
- Europe PMC abstracts;
- article full text, figures, supplementary files, or other publication content;
- Europe PMC `core` responses;
- Open Access article text merely because it is accessible through Europe PMC;
- any field introduced after a new compilation/request-plan change;
- authenticated/private API responses or credentials;
- any downstream canonical-science claim, relevance adjudication, or scientific-validity claim.

Any expansion into one of these categories requires a new rights review and, where the request identity changes, a new frozen compilation.

## Operational release rule

The current executable acquisition is a mixed-provider package. Because raw Europe PMC responses are `INTERNAL_CUSTODY_ONLY` and normalized Europe PMC candidates are `PER_RECORD_OR_CASE_REVIEW`, the global Phase 4 acquisition output must continue to carry:

`NOT_RELEASE_ELIGIBLE_UNTIL_DURABLE_CUSTODY_AND_RIGHTS_REVIEW`

This decision does not instruct the acquisition code to weaken that state. A later release mechanism must select only artifact classes explicitly cleared here and must not infer that clearing Crossref metadata also clears the Europe PMC portion of the package.

A Crossref-only derivative may be considered for public release after the durable-custody control is satisfied and the derivative is verified to contain only the cleared frozen Crossref fields plus project-generated audit metadata. That release would still represent discovery candidates, not adjudicated or canonical NeuroAI records.

## Required provenance and notices for any cleared release

Any public derivative cleared under this decision must:

1. identify the originating provider and preserve the relevant source-universe/acquisition provenance;
2. retain DOI links/identifiers in a form consistent with Crossref guidance where Crossref metadata is displayed;
3. state the frozen retrieval scope and retrieval date/execution identity;
4. preserve the distinction between provider discovery membership and NeuroAI relevance/canonical authority;
5. avoid implying open-world completeness;
6. omit any field whose rights state is more restrictive than the release artifact;
7. preserve the immutable internal custody package even when a reduced public derivative is created.

## Re-review triggers

Re-open this decision before release if any of the following occurs:

- the query compilation or selected provider fields change;
- abstracts, `core` records, full text, annotations, references, grants, or supplementary material are added;
- authenticated access, a proxy, or another client identity is introduced;
- Europe PMC or Crossref terms/documentation materially change;
- a public release would include Europe PMC record-level fields currently marked `PER_RECORD_OR_CASE_REVIEW`;
- a provider-specific license or source database restriction conflicts with this decision;
- legal counsel requires a different classification.

## Decision outcome

The required artifact-level decision is now explicit and reviewable. It clears the minimized Crossref metadata path and project-generated aggregate verification facts, while keeping Europe PMC raw custody internal and Europe PMC record-level public release fail-closed pending additional authority.

This satisfies the Phase 4 engineering/data-governance requirement to make release permissions explicit. It does not constitute legal advice and does not, by itself, authorize a production acquisition or publication event.
